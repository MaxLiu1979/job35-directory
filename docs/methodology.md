# 判定方法论 / Methodology

## 1. 活跃度（Activity）

企业被标记为"近半年招聘活跃"的唯一标准：**最近 180 天内存在可核查的公开招聘信号**。

可接受的信号来源（均为公开、无需登录）：

1. 企业官网招聘页中出现的职位发布日期
2. Greenhouse 公开接口返回的职位 `updated_at`
3. Lever 公开接口返回的职位时间戳
4. 企业官方招聘 RSS 条目的发布时间

规则：

- 有合法时间戳 → 最近一次落在 180 天内为 `active`，否则 `stale`
- 页面能访问但提取不到任何日期 → `unknown`（**不猜测**）
- 连续 180 天无信号的企业自动降级为 `stale`，恢复信号后自动回升

## 2. 35+ 友好度（Age Friendliness）

对采集到的公开文本做关键词分级（具体词表见 job35-crawler `analyze/age_friendly.py`，调整词表请提 PR）：

| 级别 | 含义 | 判定 |
|---|---|---|
| `explicit` | 明确欢迎 35+ | 出现"不限年龄""资深人才""age no bar""returnship"等公开表述 |
| `likely` | 大概率友好 | 未出现明确表述，但存在 5 年/8 年/10 年以上经验岗位等间接信号 |
| `unknown` | 暂无信号 | 采集文本中无可判定内容 |
| `risky` | 存在年龄上限 | 出现"35 岁以下""under 35"等字样，**一票否决** |

注意：

- `explicit` / `likely` 只代表**公开信号层面的友好**，不等于企业真实雇佣行为的保证，投递前请自行核实。
- 关键词判定会误伤（例如 JD 里写"团队平均年龄 35 岁以下"是描述而非限制），因此所有判定都必须附带原文摘录，人工可以复核。
- 中、英、韩、日、法多语文本的分级词表正在扩充，欢迎母语贡献者维护各自语种。

## 3. 证据规则

- 每条判定必须包含：来源 URL、原文摘录、采集时间（UTC）。
- 只接受公开可访问来源；**不接受**需要登录、付费墙、或违反目标站点用户协议获取的内容。
- 人工贡献的证据请在 `data/companies.yaml` 对应条目下以 `evidence` 字段提交，并在 PR 中说明核查方式。

## 4. 纠错与异议

企业或个人认为标注有误：在 issue 中提供公开证据链接，维护者核实后更新。
对同一企业出现互相矛盾的证据时，以时间更近、来源更权威（官方 > 媒体 > 社区）为准，并保留双方证据供读者判断。
